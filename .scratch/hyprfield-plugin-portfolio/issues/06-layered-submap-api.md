# Layered Submap API

Label: wayfinder:grilling
Type: grilling
Status: resolved
Parent: ../map.md
Blocked by: none

## Question

What simpler native-Lua declaration should replace the repeated layered submap setup in `/home/hz/.config/hypr/dimensions/keybindings.conf` and `hyprland.lua`, while preserving Super entry/exit, nested modifier layers, reset behavior, repeating binds, descriptions, and existing Hyprland primitives without owning raw key processing?

## Answer

Expose a focused `hl.plugin.layered_submap.define(...)` API using a nested,
layer-centric declaration. The declaration has one root layer and child layers;
each layer owns its bindings, layer key, and optional enter/exit action hooks.
The plugin derives routine parent/child navigation from layer keys, preserves
Hyprland's existing bind semantics, and infers sibling transitions where keys
make them available. An explicit override can edit an inferred transition for
unusual cases.

The root entry binding enters `super`. A child layer's layer key enters it from
its parent and exits that child back to its parent while active. `Escape` exits
all layers and clears the submap; there is no user-defined `reset` layer. Each
layer's exit key is therefore generated by the plugin rather than repeated in
configuration.

Bindings pass through existing `hl.dsp` action values and options, including
descriptions, repeating, locked, keyboard, and mouse behavior. The plugin adds
no dispatcher vocabulary and does not process raw key events. Structural
validation rejects duplicate names or binding identities, missing targets, and
invalid layer declarations; cycles are allowed because navigation can return
to an earlier layer.

Enter/exit hooks are optional Lua callbacks that run after a transition and
cannot consume input, redirect navigation, or mutate the declaration. Callback
failure leaves the transition applied and fails visibly through Hyprland's
built-in notification mechanism.

Canonical terms are root layer, child layer, and layer key. See the design
discussion in this ticket and the repository glossary in `CONTEXT.md`.
